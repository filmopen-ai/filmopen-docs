`PdfOpenException` with reason `pdf_open_failed` and PDFium's named error code.

reported as counts; recognition is separate from text extraction.

The native library's release licence and component notices are retained verbatim
in `third_party/pdfium/LICENSE` and shown under **PDFium** on the application's
open-source licence page.
Android packaging excludes `libpdfium.so`: PDF import is desktop only.

**The platforms of the product are Windows, Linux, Android, macOS and iOS.** Platforms enabled: `windows`; **linux** (`linux/` GTK embedder), which is also the agent layer's runner (`launch(platform: linux)` under Xvfb); **android** (a device or the emulator, driven by the agent layer over `adb`); and `web`, the debug build for previews. iOS and macOS are not configured yet; the code has branches for them (paths, file reveal) that compile but have not run. **Android is configured and runs** — a runner and a device, the app installed and driven — but has no native timeline engine yet (scenes play on the fake, §19), no release signing and no store listing, and a phone's projects live in the app's own folder.

### 3.1 Commands

```
flutter pub get            # resolves the whole workspace: one lockfile at the root
flutter analyze            # the root and every package
flutter test               # the application's own tests (test/); a package's run inside it
scripts/test_all.sh        # every suite: dart test in the pure packages, flutter test in the others and at the root (test_all.ps1 on PowerShell)
python scripts/check_catalogue.py   # the model catalogue (Project Specification §14.6–§14.9) and the pages in docs/platforms
python3 scripts/gen_plugin_api.py   # the plug-in types and reference from the interface definition; --check runs in test_all
cd packages/filmopen_l10n && flutter gen-l10n   # after editing an ARB file; commit the generated files
flutter run -d windows
flutter run -d chrome
flutter run -d web-server --web-port 8642 --web-hostname localhost   # headless preview
flutter run -d windows -t test_driver/agent_main.dart   # the agent build (§4.3): the real host, then agent.json
dart run packages/filmopen_mcp/bin/filmopen_mcp.dart serve   # the MCP server over stdio; --help lists the one-shot commands
flutter build windows --release   # build\windows\x64\runner\Release\filmopen.exe
```

The Windows toolchain needs Visual Studio Build Tools with the C++ desktop workload; `flutter doctor` must show *Visual Studio – develop Windows apps* as OK.

Application sync ownership is in `filmopen_state`, which declares `filmopen_sync` and uses its service, environment and rules contracts. No third-party dependency is introduced.
